# CelesVault WPS 文件访问诊断工具

这是**测试工具，不是正式归档应用**。它用于确认 WPS、WPS 图片查看器与资源管理器预览到底由哪些进程访问哪些文件。

**先在本机 WPS 迭代验证，学校只做最后的 Windows 10/希沃环境确认，不需要每轮都去学校。** 0.1.1 默认类型包含 PDF；启动时会显示实际配置路径和有效扩展名，不要仅凭修改源码来判断旧 EXE 已启用新类型。

- 目标系统：Windows 10/11 **64 位**。
- 需要管理员权限。运行时不需要 Rust、Node、.NET SDK 或网络。
- 不复制教学资料，不读取/保存文件内容，不截图，不记录其他应用的键盘输入，不上传数据。
- 不安装驱动、不注入进程、不修改文件关联、不设置开机启动、不启用永久系统审计。
- 采集系统文件 I/O 元数据，在内存中过滤；磁盘只保存约定目录和扩展名内的访问。诊断阶段不按 WPS 进程名提前过滤，否则可能漏掉预览宿主。
- **日志含文件名、完整文件路径、程序路径和进程 ID。请先用非敏感的测试资料，检查日志后再主动分享。**

## 一、你要准备什么

1. 把发布 ZIP 解压到本机普通目录，例如 `D:/CelesVault-Probe`。学校最后验证时也建议放 D 盘。**不要从正在测试插拔的 U 盘直接运行工具**，否则拔盘会导致日志写入失败。
2. 准备非敏感样本：
   - `Probe_Word_A.docx` 与第二份 Word 文档。
   - `Probe_PDF_A.pdf`。
   - `Probe_PPT_A.pptx`。
   - `Probe_Excel_A.xlsx`。
   - `Probe_Image_A.png`。
3. 它们必须是真实可正常打开的文件，不是只改了后缀的空文件。可新建空白 Office 文档并放入虚构内容，图片用普通测试图。
4. 把样本放在真实桌面、下载目录、D 盘测试目录及 U 盘。建议第一次先集中测试一个 D 盘目录，再验证其他来源。
5. 不需要原始教学文件，不需要管理员账号密码写进任何配置。实际部署自动收纳前，仍须明确学校与资料使用者的知情和留存授权。

## 二、启动与确认

双击 `Start-Probe.cmd`，在 Windows UAC 提示中允许本工具提权。

启动后应显示：

- 系统版本、日志目录、自动停止时限。
- 有效监听根目录和排除目录。
- 当前盘符、驱动器类型、USB 总线识别结果。
- **“ETW 已启动”及一个 `CelesVault-WPSProbe-数字-数字` 会话名。**

如果显示权限或启动错误，这次没有成功采集。不要把空日志当作“WPS 没有访问文件”。原启动窗口会保留返回码供查看。

通用默认配置的范围为当前账户的真实桌面、下载、存在的 D 盘和识别出的移动/USB 存储。**本轮本地预设包则只监听你指定的测试文件夹，默认 180 秒。**启动时以显示的根目录和实际扩展名为准。工具用 Windows 已知文件夹 API，支持常见重定向；如果提权切换了账户，路径可能不是实际使用的账户，请先检查。

新插入 U 盘后等至少 3 秒，确认控制台出现对应盘符，再开始操作。外接硬盘即使报告为固定磁盘，也会尝试检查 USB 总线；识别失败时手动添加根目录。拔盘后的历史映射会保留到本次结束，便于处理延迟到达的事件。

### 可选：修改范围

EXE 旁的 `probe-config.json` 是普通本地配置。默认示例：

```json
{
  "duration_seconds": 600,
  "extra_roots": [],
  "only_explicit_roots": false
}
```

例如只测试 `D:/ProbeSamples` 与 `E:/`：

```json
{
  "duration_seconds": 600,
  "extra_roots": ["D:/ProbeSamples", "E:/"],
  "only_explicit_roots": true
}
```

使用正斜杠可以避免 JSON 反斜杠转义。修改配置后退出重开工具。`extra_roots` 必须是绝对路径，不会扫描其中的文件内容。

## 三、如何做标记

在诊断控制台中输入一个编号，可附样本路径，按 Enter，然后切回资源管理器或 WPS 做该动作。

| 输入 | 标记含义 |
|---|---|
| `0` | 空闲基线 |
| `1` | 预览关闭，仅选中文件 |
| `2` | 预览开启，仅选中文件 |
| `3` | 双击正式打开文档 |
| `4` | WPS 已运行时，再打开另一份文档 |
| `5` | 从 WPS 内部“打开文件”入口打开 |
| `6` | 浏览图片缩略图，不正式打开图片 |
| `7` | 用 WPS 图片查看器正式打开图片 |
| `m 自己的说明` | 自定义标记，例如开启预览开关或切换到 U 盘 |
| `d` | 再次显示盘符和监听目录 |
| `?` | 显示菜单 |
| `q` | 正常结束采集，生成摘要 |

例如在控制台输入 `3 D:/ProbeSamples/Probe_PPT_A.pptx` 并按 Enter，再去双击这份 PPT。输入本身不会帮你打开文件。

标记只读取本工具控制台中主动输入的文本，不是全局键盘监听。

### 0.1.1 的实时提示

每次新标记都会重置提示阶段；未标记时，每 30 秒自动重置。每阶段最多展示 100 组“规范化路径 / PID / 操作”，打开和读取分别展示，大小写重复路径合并。达到上限会明确提示，不再像 0.1.0 那样全程到 20 组后静默停止。

“已省略提示（重复/限额）”只是控制台去重或限流，**不等于日志丢事件**。原始事件照常写盘，真正的丢失看 ETW、队列和日志健康指标。不要以控制台显示次数代替打开次数。

图片诊断会辅助识别 WPS 的 `photolaunch.exe`。系统 `Photos.exe` 若位于 WindowsApps/Microsoft.Windows.Photos，则属于 Windows 照片，不能直接当成 WPS；文件日志仍会保留范围内不同进程的访问，便于对照。

## 四、建议测试顺序（先本地，再学校最终确认）

### 本地最快一轮（约 3 分钟）

先只测试同一目录内的真实 DOCX、PDF、JPG：标记 `0` 后等待约 15 秒，依次标记并打开 DOCX、PDF、JPG；每项等 5–10 秒。再加一个新标记，重新打开同一张 JPG，确认新的提示阶段能够再次显示访问。最后输入 `q` 正常结束并检查报告。

本轮本地预设包已经限定到你提供的测试文件夹，默认 180 秒。所有步骤都可在个人电脑完成；下列课件/预览完整对照以及不同盘符测试可分轮进行。

### A. 空闲基线

工具成功启动后标记 `0`，等待约 15 秒，不操作样本。可先保持 WPS 未打开样本文档。

### B. 文档预览与正式打开对照

对 Word、PDF、PPT、Excel 各选一个样本：

1. 关闭资源管理器预览，标记 `1 样本路径`，仅选中文件，等 5–10 秒。
2. 开启预览，标记 `2 样本路径`，仅选中文件，等 5–10 秒，不双击。
3. 标记 `3 样本路径`，双击并确认文档真正出现在 WPS 中，等 5–10 秒。
4. 保持 WPS 进程运行，标记 `4 第二个样本路径`，打开另一份文档，等 5–10 秒。
5. 标记 `5 样本路径`，从 WPS 自己的文件打开界面打开一个尚未打开的样本。

`Alt+P` 通常控制 Windows 标准预览窗格，但 WPS 侧边预览可能有独立开关。请按大屏实际界面切换，并用 `m` 记录开关名称和状态。不要假定它们是同一个预览功能。

### C. 图片

标记 `6 样本文件夹`，在资源管理器中浏览图片缩略图，不打开图片。

随后标记 `7 图片路径`，用 **WPS 图片查看器**正式打开。若默认关联不是 WPS，使用“打开方式”选择它，不需要改全局默认关联。

### D. 不同来源

在下载目录、桌面、D 盘和 U 盘各验证至少一次正式打开。用标记附带路径，以便知道预期应出现的是哪份文件。

验证插拔时先关闭 U 盘样本文档，标记 `m 拔出测试U盘`，按正常方式拔盘；重新插入后等待盘符显示，再标记并打开样本。不要为了测试拔掉正在运行工具或存储日志的盘。

### E. 结束

输入 `q` + Enter，或按 Ctrl+C。等待停止会话与生成报告完成。通用配置默认 600 秒自动停止，本轮本地预设为 180 秒，以启动显示的时限为准。

**不要直接点关闭控制台窗口、强制结束进程或关机来结束正常测试**：这些操作不保证能够刷新日志或关闭 ETW 会话。

## 五、需要发回什么

每次输出到 EXE 旁的 `logs/run-时间-进程ID/`，除非通过参数指定了输出父目录。

| 文件 | 内容 |
|---|---|
| `session.json` | 系统/工具版本、实际范围、盘符、跟踪会话名、启动与停止状态 |
| `events.jsonl` | 按范围过滤后的文件事件，以及相关前台进程和设备变化 |
| `markers.jsonl` | 你主动输入的操作标签和时间 |
| `summary.json` | 健康指标及完整分组汇总 |
| `summary.md` | 可阅读的中文报告，最多展示 200 个分组 |

**先打开 `summary.md`，确认采集是否启动且正常结束。检查日志是否包含敏感文件名或路径，再只压缩本次 `run-...` 文件夹发回。**不需要把样本文档、整个 D 盘或工具的其他运行记录发来。

同时用文字附上：WPS 大致版本、WPS 图片查看器是否独立安装、哪个预览开关被使用，以及某个编号操作是否没有实际成功打开文件。无需另装诊断软件。

## 六、如何解读与能力边界

- `open_create_handle` 是操作系统打开/创建文件句柄，不直接等同于教师打开文档；预览与杀毒扫描也可能出现此事件。
- `name_*_metadata` 只用于名称映射，不是正式打开证据。
- `read` 表示文件 I/O 读取；没有 `read` 不一定意味着没有显示文档，应用可能缓存或使用不同访问方式。
- 不按进程名预先过滤，所以范围内的杀毒、资源管理器等访问也可能在日志中；这正是当前需要对照的噪声。
- WPS 临时文档或锁文件可能具有相同扩展名，诊断阶段保留它们，便于后续识别，不自动归档。
- 原始事件头 PID/TID、发起线程、关联结果及依据都被保留。未知归属不会被猜成 WPS；实时程序路径查询也不等于历史 PID 身份的绝对证明。
- 经典 File I/O 的 v2/v3 常见事件使用有长度检查的字段解码；其他事件通过 TDH 元数据读取。未知版本或读取失败会记录健康统计，不静默伪造字段。
- ETW 可能丢事件，名称映射可能不完整。路径未关联统计覆盖全系统事件，包含大量范围外文件，**不能直接换算成教学文件漏收率**。
- 事件时间与到达时间都保留。摘要按真实事件时间对齐人工标记，不因 ETW 延迟而直接归入错误操作阶段。
- 只支持有盘符的本地/USB 文件系统路径的主要场景。快捷方式的目标如果在范围外、无盘符挂载点、手机 MTP、网络或云端未落盘资料不在默认测试范围。
- 新 U 盘识别有约 2 秒轮询延迟，操作前等待至少 3 秒。启动时已打开的文件与未关联名称的事件，也可能需要重新打开验证。
- 8192 条有界队列、有限名称缓存、最多 250000 条或约 64 MiB 事件日志；达到上限自动停止并明确标记。摘要和配置另占空间。
- 每秒刷新日志，不保证强制杀进程或断电时所有缓冲事件完整。
- 一般文件 I/O 冒烟测试只能验证管道，不代表 WPS 或希沃实机覆盖率已经验证。

## 七、故障与遗留会话

启动失败时查看控制台 Win32 返回码和失败报告，不要开启更多实例试图覆盖错误。

正常结束只会停止本工具自己的独立会话，不会停止 WPR、其他调试器或 `NT Kernel Logger`。

强制杀进程后可能遗留会话。可重启机器清理；或者在管理员终端中，用 `session.json` 中的**完整** `trace_session_name` 作为 `--stop-session` 参数清理。工具拒绝非本工具格式的会话名，不执行“停止所有跟踪”。

## 开发者说明

工程位于 `tools/wps-probe`。`scripts/package.ps1` 生成便携 ZIP，不提交或推送 Git。主要检查为单元测试、clippy、构建，以及管理员权限下的 `--smoke-test`。

进程名与预览行为必须以学校日志为准，不在本工具内预置“WPS 打开成功”的结论。相关字段语义参考 [Microsoft PerfView 的 KernelTraceEventParser](https://github.com/microsoft/perfview/blob/main/src/TraceEvent/Parsers/KernelTraceEventParser.cs)，特别是名称事件中的 FileObject 实际用于 FileKey 名称映射，不能和打开句柄的 FileObject 混用。
