## 当前代码链路

1. 用户在设置中选择持久目录；程序同级 `data` 为默认建议，不自动扫描或创建正式资料库。
2. 选定后初始化 data 内 SQLite 与资料目录。程序同级 `celesvault-location.json` 只保存持久目录定位，下次启动读取；保存失败明确说明，不称为持久化成功。
3. Windows ETW 由独立 `CelesVault-Capture-*` 会话采集，复用诊断工具的路径/进程关联代码；PID动态关联、不写死。
4. 默认来源桌面/下载/D盘/已挂载USB，扩展名含Word/PPT/Excel/PDF/图片；只接配置的WPS主程序或宽松模式允许的WPS安装目录辅助程序。不直接接受Explorer/System等访问。
5. 有界事件/候选队列，回调不做摘要/复制/数据库工作。创建意图后独立归档线程流式读源，计算保存副本SHA256，检查源身份/大小/修改时间变化。
6. 自有staging同步后保存意图，用持有的文件/目录句柄不覆盖发布，再提交available。已归档主副本只读，原文件属性不改。
7. 同内容复用实体、每日未分类使用记录合并；原事件时间决定日期，不按重试完成时间。无课表时明确未分类，不生成假课表。
8. 最长40分钟先密后疏重试，失败可手动重试；原卷/文件身份变化不按同盘符误读。启动按已知任务路径恢复，不扫描全系统。
9. 前端每2秒读取状态/真实今日记录/驱动器/复制进度。目录只本地盘，不跟随junction，不暴露data内部。
10. 导出仅前端资料ID，Rust验证已归档实体，持有摘要验证租约交接到复制线程；不能从JS传任意源路径。目标目录/卷身份在操作中固定，复制后保留选择。
11. 同名默认保留两份，可跳过；明确替换与完整批次冲突预览在阶段3接入。取消只删除本任务自有暂存，不回滚已完成副本、不删原文件。
12. 托盘打开/暂停恢复/退出；错误状态变色而不抢焦点。退出请求取消同步I/O、停止自身ETW、等待后台join，不强杀线程或声称立即取消。

### Native 编译反馈（2026-11-15）

用户再次运行 app:dev，编译在 vault-core 失败。本轮修正以下原因：

- `EVENT_TRACE_LOGFILEW` 和 `OpenTraceW` 在 windows-sys 0.61.2 中由 `Win32_System_Time` 特性控制；已按本机绑定补齐该特性，不改为编译器提示的相似名称或自定义替代类型。
