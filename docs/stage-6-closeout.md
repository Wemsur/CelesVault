## 修改前的复现与证据清单

用户现象：触屏依然无法滚动；此前曾有课程到顶后延迟跳转。

静态证据：ArchiveTile用TouchEvent手动滚动、PointerEvent只处理pen，tile的touch-action:none禁止原生平移；DirectoryBrowser独立PointerEvent手动滚动且仅文件夹处理，普通文件/空白走另一条路径；课程空白走原生平移及mandatory snap。三个事件所有者无法保证相同的Windows/远程触控输入路径，按钮/失败层又可能拦截叶子事件。尚无当前设备事件轨迹，不能声称已证实具体WebView/设备根因。

已在源码中统一为滚动容器捕获阶段的一套PointerEvent状态机，touch/pen短滑滚动、450ms后才拖动，鼠标沿用已有路径；旧ArchiveTile TouchEvent滚动和目录touch/pen独立分支已移除。移动超过8px后锁定方向、停止长按并暂停snap，课程内部先消耗纵向滚动，同向边界交给课程外层；只有外层实际移动才在松手时吸附，首末边界保留。目录普通文件/文件夹/空白、固定夹和库网格/列表共用此路径，按钮轻点不拦截，滑动后的合成点击被抑制。指针捕获只在确定滑动/长按后取得，忽略子元素隐式捕获转移产生的lostpointercapture，取消/切页/失焦清理资源。

“设置 → 数据与诊断”显示触点能力、鼠标输入次数、本会话触控输入类型、区域、开始/滑动/长按/取消计数与实际滚动累计，诊断导出含相同白名单字段，不含文件名、路径、坐标，不上传。实际位移为0不能记作已滚动成功。用户设备未复验，不能将上述源码变化称为已解决实机触屏问题。

| 场景 | 修改前反馈/依据 | 完成门槛 |
|---|---|---|
| 左右分屏从空卡、标题、文件、按钮附近上下划 | 用户报告无法滚动；输入路径不一致 | 跟手滚动、不误选、不误开菜单 |
| 上下分屏左右划；有溢出的文件区上下划 | 内外滚动/snap竞争 | 文件内先滚，边界才交外层；方向正确 |
| 滚到最上/下后停留多次轮询 | 已有延迟跳转反馈 | 首末边界稳定，轮询不拉回 |
| 库网格/列表，空白、正常/失败文件表面滑动 | leaf touch-action禁用原生 | 都能滚，不误打开或重试 |
| 目录文件、文件夹、空白短划 | 目录仅folder接手动pointer | 都能滚，文件夹长按仍可固定 |
| 固定区多项触屏滚动 | 原生与手动路径分离 | 跟手滚动，短划不导航 |
| 停留后拖归档/拖文件夹 | 必须与短划区分 | 原选择规则、目标快照保持，松手才提交 |
| 多指、取消、失焦、切页、换方向、卸载 | 需完整清理 | 不遗留拖影/计时器/snap禁用，不提交取消动作 |

以上均待真实设备复验；未执行任何测试或dev。复验时先记下设置中的计数，在课程/库/目录分别划动后再次读取：开始计数不增而鼠标计数增，表示远程/设备输入被转成鼠标；开始增但实际位移为0，需说明触摸起点和是否确有溢出；取消计数频繁增加，记录是否切页/失焦/多指。缩放75%、100%、200%分别复验，手势位移已按实际布局比例换算，不重复放大。
