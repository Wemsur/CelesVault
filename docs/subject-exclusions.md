# 科目排除与监测重启

日期：2026-11-20。此文描述已写入的源码及待验收边界，不代表 Windows 编译、ETW 或学校验证通过。

## 使用方式

在“设置 → 监测 → 排除科目”勾选科目，再点击“保存”。科目来自“课程与课表”，以稳定 ID 而非显示名称匹配。取消草稿不改变已保存策略；从课表移除的科目 ID 仍保留排除，可主动解除。

这是按**课表时间归属**的排除，不读取资料内容判断学科。课前和课间仍归属当日下一启用课程；被排除课程不会被跳过而误收进其他课程或未归类。没有下一节、无课日仍依照原规则归未归类；务必先配置正确课表和系统时间。已完成的历史资料不自动删除。

## 源码策略

- CaptureSettings 新增 `excludedSubjectIds`，旧配置缺少该字段时默认为空；未知字段和非法类型仍拒绝。配置导入只是草稿，保存才生效。
- ETW 候选在本应用打开源文件元数据前进行只读归属预判；正式接受时再次检查。不为被拒绝候选登记路径、别名、任务或使用记录，也不为该候选创建日快照。ETW 本身仍接收系统文件事件，不宣称系统层完全不产生或暂存这些事件。
- 修改排除列表采用 stop–commit–resume：先阻止准入，取消并等待旧捕获/归档线程退出，再持久保存，设置新的事件水位，恢复原数据根和暂停状态。正在应用时不能当成已保存；停止期间旧策略下已完成的资料保留，不能承诺倒退撤销已经发生的读取。
- 待处理、失败重试、暂存恢复、去重及发布检查当前关联课程的稳定科目 ID。排除任务不因重启或重试改归其他科目绕过限制；旧任务归属无法确认时，在存在排除规则的情况下保守阻止。未知既有暂存文件不自动删除。
- SQLite schema 从 v2 升至 v3，新增任务归属可信标记；旧 v1/v2 数据迁移源码已写，尚未执行验证。首次用新版前请在正常退出后保留完整 data 备份；不要同时用旧程序打开升级后的库。

## 重启监测服务

同一监测页的“重启监测服务”仅重启当前应用的监测与归档后台，不安装 Windows 服务、不重启整台电脑、不删除资料。先保存或放弃草稿，按钮才可用。保留暂停状态，中断的 copying 意图仍须通过现行策略才能恢复。

停止等待有 15 秒边界。若无法确认线程已退出，保留旧线程所有权并报错，禁止启动第二组后台。若 ETW 停止结果不可靠，会维持拒绝重启；不要通过连续点击期待强制替换。配置已保存但恢复失败时会明确报错，此时不能把失败提示理解成配置一定没写入。

## 开发残留

`app:dev` 已接开发包装器，只向当前项目有认证记录、PID/创建时间/EXE 路径再次核实的旧实例请求正常退出。不会按同名杀进程、清理全局 Node/Cargo、按端口杀进程或批量停止未知 ETW。它覆盖再次启动 app:dev 前的清理，不接管 Tauri 每一轮 Rust 热重载；详情见 [开发实例清理](dev-lifecycle.md)。

本地诊断导出改用状态和计数白名单，不导出 runtime/status/jobs 的原始路径或错误字符串。配置导出仍含用户配置的路径、规则、科目和收藏，不应当作脱敏诊断公开发送。

## 待用户验收

助手未运行构建、编译、cargo check、测试、类型检查、lint 或 Native dev。新增回归测试仅写入源码。当前只能认定实现与静态接线已完成，不能据此投入课堂。

- [ ] 用旧配置及旧数据副本启动，确认迁移、镜像一致和排除默认为空。
- [ ] 添加两科及相邻时段，排除其中一科；分别测试课前、开始、结束前、课间、最后一课后及跨日。
- [ ] 被排除时间打开 WPS DOCX/PDF/图片，没有新增归档或因排除而转入其他课次；允许科目正常归档。
- [ ] 保存排除时已有待办、失败重试和正在复制任务，保存完成后不继续产生被排除科目的新归档；旧已完成资料仍在。
- [ ] 取消设置草稿不改变策略；保存后退出重开仍保留；改名不解除排除，移除科目后旧排除仍显示。
- [ ] 暂停后重启仍暂停；正常状态反复重启没有重复后台；停止失败显示错误而非运行成功。
- [ ] 停止旧开发终端后再次 app:dev，已登记旧实例先正常退出；其他路径的副本不受影响。
- [ ] 旧版未登记进程、PID 不匹配、端口冲突、权限不足和未知 ETW 不被自动清理。
