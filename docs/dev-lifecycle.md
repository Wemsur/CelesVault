# Windows 开发实例清理

`pnpm run app:dev` 只使用默认的 Cargo debug 产物 `target/debug/celesvault.exe`。仍按现有应用要求从管理员终端手动运行，包装器不请求提权；不会更改 Vite 的 8006 严格端口。不要在同一检出目录同时启动多个开发终端；再次启动前先停止旧的 Tauri 监听器。包装器的按项目命名管道只避免同一项目的包装器互相抢跑，不负责发现或管理其他监听器。

- 每次启动生成随机会话和令牌，令牌通过进程环境继承，也保存在 Git 忽略的 `target/celesvault-dev` 中的会话票据。应用确认票据与环境匹配，发布认证的 PID、Windows 进程创建时间和规范化 debug EXE 路径。普通 debug 直接启动、其他构建目录及发布包不登记。
- 新启动器用只读 Windows 查询重新核对登记的 PID、创建时间及实际映像路径。只有仍匹配的旧实例才收到针对该次运行的认证退出请求；应用将其交给现有的 `app.exit(0)` 和 `ExitRequested` 停机流程，不发送关窗消息。旧进程未退出或权限不足以验证时，不启动替代实例。超时后原退出请求可能仍在处理中。
- 票据属于本地可信工作区，依赖工作区的 Windows 文件权限；它不是对能读取票据或修改工作区的本地程序的权限边界。不要公开会话目录或提交票据。
- Rust 热重载产生的新应用进程会在继承会话环境后单独登记，但包装器只在执行 `app:dev` 时清理，不接管 Tauri 每次热重载的内部结束逻辑。包装器异常结束后，原 Tauri/Vite 监听器也可能仍在运行。

**遇到未知残留时：** 首次接入前启动的应用、未登记的应用以及其他副本都不会被自动认领。先查看旧开发终端，或在任务管理器「详细信息」中核对 PID 和「打开文件所在的位置」，再从确认为自己的旧实例的托盘菜单选择「退出」。如果 Vite 报端口占用，请检查并停止自己启动的旧开发终端；端口或进程名不是终止权限。没有强制清理选项，也不会扫描或停止 ETW 会话；如果现有诊断报告残留会话，记录其完整名称供人工排查，不按前缀批量停止。所有本项目开发进程退出后，可以手动删除 `target/celesvault-dev` 的遗留票据。

## 接线与验证状态

`src-tauri/src/lib.rs` 已在 Windows debug 条件下声明模块，并在 `.setup` 成功路径调用 `dev_lifecycle::start(app.handle().clone())`。现有 `ExitRequested` 停机处理未改变，发布构建不编入此握手模块。

源码接线已完成，未运行构建、检查、测试或 Native 开发进程，不能声称清理功能已通过 Windows 验证。需由用户验收：正常启动与退出、热重载后的身份登记、旧实例退出后才启动、PID 不匹配不处理，以及其他副本和端口冲突不误伤。
